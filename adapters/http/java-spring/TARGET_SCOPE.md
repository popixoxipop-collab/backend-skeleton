# HTTP-java-spring-01 target scope

Status: **static fixture and evidence plan**, not production certification. Prerequisite T11-02 is MET. This target owns only `adapters/http/java-spring/**`.

The default Java Spring scan is static. Detection requires a Gradle or Maven build file with a sibling `src/main/java`; source discovery uses ripgrep. The scanner recognizes literal Spring MVC controller mappings, selected single-verb `@RequestMapping` forms, operation-id annotations, JPA entity facts, Spring Data REST declarations, module attribution, and global-prefix warning signals. It is a masking and balanced-delimiter structural scan, not a Java compiler, Spring application context, or general AST/symbol solver.

The committed fixture pins a Spring Boot **3.3.0** build marker and is scanned rather than built. Required pull-request CI uses Java **17** for Java jobs. The scheduled Initializr canary separately requests Java **21**, but its server-selected Spring Boot version is not pinned here and the canary is not a runtime-equivalence proof for this target. No other Spring Boot or Java version range is certified.

The oracle manifest pins `spring-projects/spring-petclinic`, `ali-bouali/spring-security-asymmetric-encryption`, and `1chz/realworld-java21-springboot3` at exact 40-character Git commits. Those pins describe three immutable source shapes only. `npm run test:oracle-corpus` is a network-heavy diagnostic and is not run by default CI. No external application is booted by this target, and scanner-versus-runtime route equality remains **NOT VERIFIED**.

Must-catch cases: deterministic same-input fixture output; literal class and method mappings with operation-id provenance; explicit table and UUID primary-key facts; Spring Data and inherited-id limits; nested project-root detection; global `configurePathMatch`, servlet context-path, and springdoc prefix signals; dynamic annotation constants or route factories; multi-verb `@RequestMapping`; unknown module attribution; exact real-oracle revisions; Spring Boot/Java version boundaries; and truthful absence of runtime or release authority.

Dynamic annotation constants and factories such as `@RequestMapping(ApiPaths.ROOT)` or `@GetMapping(RouteFactory.item())` are **NOT VERIFIED**. Their argument text can be observed structurally, but the scanner does not evaluate Java constants, execute factories, or prove the resulting route. Multi-verb mappings are likewise left unresolved rather than guessed. Global prefixes are emitted as warning signals and unknowns; they are not silently prepended to static controller paths. A real OpenAPI document supplied through the existing explicit trust-boundary path is required for higher path accuracy.
