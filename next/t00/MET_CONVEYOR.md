# T00 MET closure conveyor (read-only)

Run the offline task triage with two **externally verified** source files: the original 291-task plan backlog and the official `t00.task-audit/2` snapshot. Pass the SHA-256 of each file independently. The tool rejects missing/duplicate task IDs, non-DAG dependencies, changed counts or source digest mismatches.

Usage:

```sh
python3 next/t00/met_conveyor.py --plan /absolute/path/backlog.json --audit /absolute/path/T00_TASK_AUDIT.json --plan-sha256 <64-lowercase-hex> --audit-sha256 <64-lowercase-hex> --out-dir /absolute/fresh/output
```

The output contains a deterministic `triage.json`, `brief.md`, a SHA-bound `receipt.json`, `work-packet-index.json`, and incomplete proof request templates in `work-packets/`.

Validate the generated bytes separately (integrity checks, **not external author authenticity**):

```sh
python3 next/t00/verify_met_conveyor.py --directory /absolute/fresh/output
node --test test/t00-met-conveyor.test.mjs
```

The targeted fast workflow `T00 MET Conveyor Fast Check` tests these changes on pull requests. Its success provides no release or MET credit and cannot replace the full cross-repository signed release CI. **MET delta is always zero.** Candidate readiness and priority scores are heuristics, not source or runtime certification. No GitHub repo, T00 source, release, or production state is modified.

Each packet records the official original gap, direct unfulfilled predecessors, required tests, source paths, and **null proof slots**. An independent authenticated auditor must verify merged product SHA, normal and negative fixture logs, packed consumer, exact-version runtime/oracle, CI, reviewer/lease, and issue-specific acceptance before any authorized T00 CAS adjudication.

The existing T00 audit remains the only numerical authority. A successful script run certifies neither support for 49 frameworks nor global release readiness; the absence of independent attestation remains a release blocker.
