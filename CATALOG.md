## Top 5 Priorities (Codex's own ranking, verbatim)

1. **Gate Engine v2: declarative dependencies, accurate invalidation, and history**

   Gates are the product's core differentiator, but current recomputers overstate their coverage: `handles` does not hash generated files, `stack` hashes only `.sbf/stack.json`, and `preflight` cannot notice a newly advanced remote tip. Move gate definitions, dependencies, input/output manifests, and verification policy into one registry before adding more phases.

2. **Make OpenAPI the typed contract plane**

   `buildContract()` currently derives only verb, path parameters, and a body-present boolean; this also causes the documented response/error gap and operation-correlation misses. A normalized OpenAPI 3.0/3.1 import and reconciliation layer delivers richer request, response, error, query, security, and cross-framework contracts, so it should precede both DB introspection and a heavier Java parser.

3. **Productionize handles before automating `patchField()`**

   `emitHandles()` unconditionally overwrites shared infrastructure and resolver files, while the generated controller does not enforce registry membership/revocation, field fetch always returns 501, and no code writes registry or snapshot records. First establish artifact ownership, a fail-closed authorization model, mint/register/snapshot lifecycle, and safe field reads; only then add assisted patch generation.

4. **Introduce a capability-based adapter IR and prove it with FastAPI**

   The Java scanner and downstream generators exchange an implicit, Spring-shaped object model, while `generic-grep` returns one `_generic` module with unknown verbs and no usable operation IDs. Define a versioned framework-neutral IR, then build FastAPI as the second first-class adapter because Python AST plus OpenAPI/Pydantic metadata provides a tractable validation of genuine portability.

5. **Turn the CLI into an installable onboarding product**

   The repository has no README, `package.json` is `"private": true`, there is no repo-level `bskel init`, and the hand-written flag parser produces inconsistent human/JSON errors. A packaged CLI with `init`, `status`, `next`, strict argument handling, installation smoke tests, and a minimal getting-started path is the shortest route from a personal skill to repeatable adoption.

### A6. OpenAPI export: render an emitted contract back out as a standalone document

- **What:** `bskel contract export --feature <id> [--out <path>] [--json] [--allow-unprefixed] [--status-codes range|literal]` — render an already-emitted, gate-passing feature contract as a standalone OpenAPI 3.1 document (stdout by default).
- **Why:** A1 built the import direction and A2/A3 made it load-bearing — `python-fastapi`, `typescript-express` and `javascript-express` all declare `api.operations: false` and depend on `--openapi-file` for any contract at all. There is no way back out today. The internal contract — feature-scoped, single-module, fully `$ref`-inlined (`inlineSchema()` already guarantees zero `$ref`) — is more useful than the source repo's own full OpenAPI document for three real consumers: a Swagger UI page scoped to one feature instead of the whole repo; a client generator that chokes on `$ref`; a mock server/gateway config for one feature's operations.
- **Scope/Effort:** **M** for the exporter + **S** for two importer fixes it forces.

Never synthesize what the contract does not know — disclose every omission in prose (`info.description`) and machine-readably (`info.x-bskel-omitted`), and omit `security` entirely rather than emitting `security: []`. Map `responseSchema` → `responses["2XX"]` and `errorSchema` → `responses["default"]`, omitting `responses` when the contract has neither. Gate on the `contract` gate having passed; refuse a `blocked` contract, and refuse by default when the scan found a global path-prefix signal the contract's own paths don't reflect. ### A7. Source-backed OpenAPI field passthrough (lossless slice of a real document)

- **What:** Copy query/header/cookie parameters, `security` (+ referenced `components.securitySchemes`), `summary`, and `tags` from a real `--openapi-file` source document onto matched/adopted contract operations — `sourceParameters`/`sourceSecurity`/`sourceSummary`/`sourceTags` per operation, `sourceSecuritySchemes` at the contract root — and emit them on `contract export`. Phase 1 only; per-status responses, non-JSON media types, and operation `description` are Phase 2, not built here.
- **Why:** A6's own "never synthesize" constraint left the contract carrying none of these fields for ANY operation, even when a real, human-supplied, already-validated `--openapi-file` document said something concrete about that exact operation — a gap in what A1's `indexOpenApiDocument()` retained off the source, not a permanent limit on what an export may say. `security` is the sharpest case: A6 refused to ever emit `security: []` because inventing it is a false claim; copying a source document's own `security: []` is the opposite — the document's own positive claim, transported, not invented. Measured on the real 148-operation Team-IZ-Backend oracle: 33/148 operations have query params, 23/148 header params, 2/148 cookie params, 148/148 have an explicit `security` (137× a real bearer requirement, 11× a genuine `security: []`), and 148/148 have `summary`/`tags` — all previously unrepresentable by this projection.
- **Scope/Effort:** **M**, comparable to A6's exporter half. Default-on whenever `--openapi-file` is given (measured ~234 bytes/operation across 9 real modules) — no new CLI flag.
- **Concrete approach:** Mirror `inlineSchema()`'s COPIED/DROPPED/fail-closed keyword-policy shape one level up for the Parameter Object (`copyParameter()`); a `$ref`/`content`-keyed/unrecognized-key parameter fails closed for that ONE parameter, never the whole operation, and a parameter whose `schema` alone fails to resolve is still copied without the `schema` key (exporter fills `{}`). `security` is all-or-nothing per operation — a requirement naming an unresolvable scheme drops the WHOLE value, never a dangling reference (the meta-schema cannot itself catch a dangling security-scheme reference or a duplicate `(name,in)` parameter, confirmed by executing it).
